# دليل مسؤول النظام — TPS System (Windows / localhost)

## حدود الصلاحية

إدارة TPS الحالية محلية. لا نشر خارجي، ولا تعديل لرايات، ولا وصول إلى بيانات متدربين شخصية من خلال الاختبارات. يحتفظ `main` بالإصدار المستقر؛ التطوير في `feat/full-stack-tps-v1` ضمن PR #8 المسودة. لا تدمج PR ولا تنشر التطبيق قبل القبول.

## التثبيت المسموح لكودكس لاحقًا

1. افحص `<LOCAL_TPS_DIR>` باستخدام `git status`، واحفظ أي تغييرات غير مرفوعة. لا تستخدم `git reset --hard` أو `git clean` أو حذف Docker volumes.
2. تحقق من Node 22+، Java 21، Maven، Python 3/openpyxl، Docker Desktop والمنافذ المحلية.
3. أنشئ `.env` خاصًا بالمشروع من `.env.example` دون تسجيل كلمات المرور أو رفعها.
4. شغّل PostgreSQL محليًا، ثم `npm run db:migrate` و`npm run db:check`، وتحقق من الترحيلات `0001–0011`.
5. أنشئ أول مستخدم إداري عبر `TPS_BOOTSTRAP_PASSWORD` المؤقت و`npm run db:bootstrap`، ثم امسح متغير البيئة.
6. ابنِ الواجهة والخادم والمحرك: `npm run build`, `npm run web:build`, `npm run solver:build`. افتح `http://127.0.0.1:8787`.
7. نفذ الاختبارات على قاعدة بيانات **اصطناعية منفصلة**، ثم تحقق من بقاء السيناريوهات بعد إعادة تشغيل PostgreSQL دون حذف الحجم الدائم.

تفاصيل الأوامر: `docs/DEPLOYMENT_LOCAL.md` و`docs/CODEX_LOCAL_HANDOFF.md`.

## التحكم بالوصول

الأدوار الأساسية في النظام: `SYSTEM_ADMIN`، `COLLEGE_ADMIN`، `DEPARTMENT_HEAD`، `SCHEDULER`، `REVIEWER`، `APPROVER`، `TRAINER`، `VIEWER`. تتحقق API من النطاق التنظيمي قبل الوصول؛ إخفاء أزرار الواجهة وحده لا يُعد حماية. لا تُفعّل وضع تدريب غير حضوري لمقرر بمجرد تعديل سياسة الفصل أو استيراد Excel.

- كلمات المرور: Argon2id، والجلسة مخزنة في PostgreSQL مع cookie HttpOnly/SameSite.
- تغييرات البيانات: جلسة فعالة وCSRF وصلاحية القسم/الكلية المناسبة.
- اعتماد السياسات والاستثناءات والجداول: أدوار مخولة وسجلات تدقيق وموانع جاهزية.
- استيراد الملفات: معاينة ثم commit للملف المطابق للبصمة الأصلية، مع رفض محاولات إعادة الاستخدام.
- Timefold: محاولات حل مسجلة في `solver_runs`، والإلغاء النشط مقيّد بالخادم المحلي ومصرح ومُدقَّق. التعافي للمحاولة المهجورة بعد دقيقتين، وليس زر إيقاف Java.
- لا تحذف سجلات معتمدة أو سيناريوهات محفوظة لإصلاح الاختبارات.

## المتابعة والقبول

عند فشل عملية، افحص الخطأ المسجل وسجل التدقيق و`solver_runs` ونتيجة `readiness` دون عرض أسرار أو بيانات شخصية. وثق الأمر والتاريخ والبيئة ونتيجة pass/fail/skip والسبب.

لا تعتبر التشغيل المحلي مكتملًا إلا بعد مراجعة `docs/ACCEPTANCE_MATRIX.md` والرحلة الفعلية من الدخول حتى تصدير سيناريو معتمد. لا تدّعِ وجود موافقة مؤسسية أو تكامل رسمي مع رايات؛ صلاحيات TPS داخلية للتخطيط فقط.

## الأرشفة الآمنة — الترحيل 0014

يمكن أرشفة المقررات والمدربين والقاعات وإعادتها للعمل بمبرر مدوّن، دون حذف السجلات أو المساس بالسيناريوهات السابقة. يجب تفعيل القاعة المشتركة من صلاحية إدارة الكلية. لا يمكن أرشفة مقرر داخل خطة تدريبية نشطة قبل معالجة إصدار الخطة، ولا يُسمح ببناء سيناريو جديد بمقرر مسند إجباريًا لمدرب مؤرشف. يجب على كودكس فحص الاستبعاد من السيناريو الجديد، ثم الاستعادة، واستمرار ظهور اللقطات السابقة كما هي في قاعدة اختبار مستقلة.
