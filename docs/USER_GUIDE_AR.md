# دليل المستخدم — TPS System (نسخة التطوير المحلية)

**نطاق الدليل:** الوظائف الموجودة حاليًا في واجهة React العربية. النظام أداة تخطيط محلية، وليس نظام رايات أو بوابة لاعتماد الجداول رسميًا. استخدم بيانات اصطناعية في التجربة.

## بدء العمل

افتح `http://127.0.0.1:8787` بعد تشغيل الخدمات محليًا. سجّل الدخول بالحساب الذي أنشأه مسؤول النظام (لا توجد كلمة مرور افتراضية في الشيفرة). اختر الكلية والقسم والفصل التدريبي؛ يحتفظ المتصفح بخيارات العرض، بينما تتحقق الواجهة الخلفية من صلاحية كل عملية.

## الرحلة التشغيلية

1. **الهيكل والفصل:** اختيار المؤسسة/الكلية/القسم والفصل، أو إنشاء السجلات إن كانت لديك صلاحية.
2. **المقررات والخطط:** أضف مقررًا، أو افتح شاشة الاستيراد وحمّل قالب CSV/XLSX. استعرض الصفوف والمشكلات أولًا، وصحح المصدر ثم اعتمد الاستيراد صراحة.
3. **الطلب والبلوكات:** أدخل الطلب ومصدر التقدير، وربط البلوكات بالمقررات. اختلاف مجموع أحجام البلوكات والطلب يمنع بناء سيناريو صحيح، ولا يُسمح بتكرار النظري والعملي في العدد.
4. **المدربون والقاعات:** أدخل المدربين وأهليتهم وأنصبتهم وإتاحتهم، وأدخل القاعات وسعاتها وأنواعها. تحتاج استثناءات النصاب إلى اعتماد مستقل.
5. **أنماط التدريب:** الحضوري هو الافتراضي. تفعيل عن بُعد أو الذاتي أو المدمج على مستوى سياسة الفصل لا يغيّر أهلية المقرر تلقائيًا؛ يلزم قرار داخلي مستقل. المدمج يحتاج تقسيمًا صريحًا لساعاته.
6. **إنشاء سيناريو:** توليد مسودة يظهر الشعب والعجز. المسودة الناتجة عن Greedy ليست نتيجة Timefold وليست جدولًا معتمدًا.
7. **تشغيل Timefold:** اختر مدة بين 1–30 ثانية وعدد بدائل بين 1–24 لكل مدرب، واضغط تشغيل. يمكنك إلغاء التشغيل النشط عبر سجل العمليات إذا كنت مخولًا؛ الإلغاء لا يحفظ جدولًا جزئيًا.
8. **فحص الجاهزية:** افتح التحذيرات المرتبطة بالشعب، وقارن القيود والأنصبة والعجز، وتحقق من البلوكات.
9. **التعديل اليدوي:** استخدم الجداول الأسبوعية بأربع طرق عرض (المدرب، القاعة، المستوى، البلوك). السحب والإفلات يعرض اقتراحًا لا يُحفظ إلا بعد التأكيد وسبب التعديل وفحص Backend للقيود.
10. **السيناريوهات والاعتماد:** أنشئ نسخة بديلة للمقارنة؛ السيناريو الموافق عليه يحفظ لقطة ثابتة. أي تعديل لاحق يحتاج نسخة أو مراجعة جديدة. لا يُقبل اعتماد جدول يتضمن موانع جاهزية.
11. **التقارير:** صدّر CSV أو Excel عربيًا، أو استخدم التقرير الموجز للطباعة/حفظ PDF من المتصفح. التقرير يعكس السيناريو المحفوظ ويبيّن حالة اعتماده داخل TPS.

## رسائل مهمة

- **403**: لا تتوفر صلاحية أو فشلت حماية CSRF.
- **409**: تعارض في حالة السيناريو، إصدار تعديل قديم، أو عملية محرك جارية/منتهية.
- **عجز غير مغطى**: لا يُعد تحويل المقرر إلى تدريب عن بُعد حلًا تلقائيًا؛ يحتاج نمطًا وأهلية معتمدين.
- **بلوك غير محدد**: لا يُعلن خلو تعارضات المتدربين دون بيانات كافية.
- **CANCELLED**: محاولة المحرك أُلغيت؛ السيناريو لا يصبح معتمدًا، ويمكن إعادة المحاولة عندما تنتهي عملية Java السابقة.

## حدود النسخة

لا تستخدم بيانات المتدربين الشخصية في التجربة ولا تنشر جداول في رايات. بعض واجهات الإدارة والقيود المتقدمة واختبارات القبول الكامل لا تزال قيد التطوير؛ راجع `docs/FULL_MANDATE_GAP_REVIEW.md`، ولا تعتبر نجاح الاختبارات الاصطناعية اعتمادًا من الكلية.
